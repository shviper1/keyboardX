# KeyboardX

A custom iOS 15+ Keyboard Extension built with Swift and UIKit that replicates the classic iOS stock keyboard look and feel while adding power-user features:

1. **Stock Visual Design & Feedback**
   - Dynamic Light Mode and Dark Mode palettes (honoring both system traits and the host text field's `keyboardAppearance`).
   - Standard iPhone QWERTY layout, `123` numbers page, and `#+=` symbols page with native-matching proportions, 5 pt corner radii, 1 pt key bottom shadows, and SF Symbols (`shift`, `shift.fill`, `capslock.fill`, `delete.left`, `globe`).
   - Balloon key popovers on character press, plus standard system keyclick audio via `UIDevice.current.playInputClick()` (`UIInputViewAudioFeedback`).
   - Shift, double-tap Caps Lock, sentence/word auto-capitalization, double-space → `". "`, and backspace hold auto-repeat.

2. **Long-Press Power Shortcuts (Conflict-Free)**
   - **Hold `V` (0.5 s) → Paste**: Reads `UIPasteboard.general.string` and inserts it into `textDocumentProxy`.
   - **Hold `C` (0.5 s) → Copy**: Copies `textDocumentProxy.selectedText` if present, or extracts the word touching the cursor from `documentContextBeforeInput` / `documentContextAfterInput`, writes it to `UIPasteboard.general`, and saves it to the clipboard history.
   - **Hold vowels (`A`, `E`, `I`, `O`, `U`) → Accent picker**: Slide horizontally to choose an accented variant (`é`, `ö`, etc.).
   - Touch handling is managed centrally in `KeyboardView` via per-touch `DispatchWorkItem` timers rather than `UILongPressGestureRecognizer`, so `V`/`C` shortcuts never conflict with vowel accents and lifting your finger after a shortcut fires never inserts `"v"` or `"c"`.

3. **Gboard-Style Clipboard Manager**
   - A 44 pt bar above the top row (which also gives top-row key popovers room to render without clipping) displays a horizontally scrollable strip of recent clipboard chips (up to 15 items).
   - Tap any chip to insert it immediately; long-press a chip to delete it; tap the 📋 icon to expand a 2-column full-keyboard panel with individual delete buttons and **Clear**.
   - History is persisted in an App Group (`group.com.yourname.keyboardX`) so both the keyboard extension and the container app can view and manage it.
   - Items marked concealed/transient by password managers (`org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType`) are ignored.

## Generating the Xcode Project

1. Install [XcodeGen](https://github.com/yonaskolb/XcodeGen) if you don't already have it:
   ```bash
   brew install xcodegen
   ```
2. Before generating, replace the placeholder identifiers if desired:
   - Bundle ID prefix `com.yourname` in `project.yml`
   - App Group identifier `group.com.yourname.keyboardX` in:
     - `Shared/AppGroup.swift`
     - `KeyboardExtension/KeyboardExtension.entitlements`
     - `KeyboardXApp/KeyboardXApp.entitlements`
     - `project.yml`
3. Generate and open the project:
   ```bash
   xcodegen generate
   open KeyboardX.xcodeproj
   ```
4. In Xcode, select your **Development Team** under **Signing & Capabilities** for both `KeyboardXApp` and `KeyboardExtension`, then build and run `KeyboardXApp` on a simulator or device.
5. On the device/simulator, open **Settings › General › Keyboard › Keyboards › Add New Keyboard…**, add **KeyboardX**, then tap **KeyboardX** and enable **Allow Full Access**.

## `Info.plist` Configuration Explained (`KeyboardExtension/Info.plist`)

```xml
<key>NSExtension</key>
<dict>
    <key>NSExtensionAttributes</key>
    <dict>
        <key>IsASCIICapable</key>
        <false/>
        <key>PrefersRightToLeft</key>
        <false/>
        <key>PrimaryLanguage</key>
        <string>en-US</string>
        <key>RequestsOpenAccess</key>
        <true/>
    </dict>
    <key>NSExtensionPointIdentifier</key>
    <string>com.apple.keyboard-service</string>
    <key>NSExtensionPrincipalClass</key>
    <string>$(PRODUCT_MODULE_NAME).KeyboardViewController</string>
</dict>
```

- **`NSExtensionPointIdentifier = com.apple.keyboard-service`**: Declares the target as a system-wide custom keyboard extension.
- **`NSExtensionPrincipalClass = $(PRODUCT_MODULE_NAME).KeyboardViewController`**: Points iOS to our `UIInputViewController` subclass.
- **`RequestsOpenAccess = true`**: Adds the **Allow Full Access** toggle in Settings. Full Access is required by iOS for:
  1. Reading and writing `UIPasteboard.general` (needed by the `V` paste shortcut, `C` copy shortcut, and the clipboard bar).
  2. Sharing `UserDefaults` with the container app via the App Group.
  3. Audible keyclicks (`UIDevice.current.playInputClick()`) and `UIImpactFeedbackGenerator` haptics.
  When Full Access is off, KeyboardX degrades gracefully: typing works normally, the clipboard bar displays instructions to enable Full Access, and holding `V`/`C` shows an informative toast instead of failing silently.
- **Note on `RequestsSupplementaryLexicon`**: This key grants access to a `UILexicon` of contact names and user text replacements for autocorrect. It does **not** grant clipboard access, so it is omitted here.

## Known iOS Platform Limitations

- **Background clipboard monitoring**: iOS suspends keyboard extensions whenever the keyboard is hidden. Copies made while KeyboardX is visible are captured immediately (via a lightweight 1 s `UIPasteboard.general.changeCount` check), and the most recent item copied while the keyboard was hidden is captured the next time KeyboardX appears (or when the container app becomes active).
- **Visual text selection on Copy**: `UITextDocumentProxy` does not expose an API to create a visual text selection in the host app. Holding `C` copies `selectedText` if the user already selected text, or otherwise copies the word touching the cursor and confirms with a toast (`Copied ‘…’`).
